## Focused corrections

- Read-only job lookup and foreground/restart reattachment restore the saved server status. Reattachment never posts a start/retry request or publishes an edition.
- A canonical PDF/prompt-revision job identity ignores editable display metadata; compatible legacy jobs retain their IDs and checkpoints. Concurrent retries share the transactional generation. An explicit retry reuses completed checkpoints, including those from an expired job.
- Worker cancellation is generation-fenced. Discard waits out an active worker lease before removing PDF bytes. Existing per-draft client write fences prevent stale clients republishing/recreating a discarded draft.
- The manual callable rechecks approved Admin/VIP authorization, revocations, actual live default-rules hash, maintenance coordination, publication references, derived records and holds. It deletes only verified native manifests, their chunk namespace and selected analysis metadata. Unknown subcollections or historical Storage objects stop cleanup explicitly; they are never recursively deleted or inferred to be owned from a URL.
- The client retains a pending-discard entry for retry and removes the false automatic-cleanup claim.

Completed checkpoints are not reprocessed. As with the existing external model integration, a process crash after a provider response but before its checkpoint commits can repeat that unfinished batch; this is not a guarantee of exactly-once provider billing.

## Deployment scope

The default-rules pin is intentionally fail-closed and must be reviewed when those rules change. Storage-held drafts require a separate ownership review, not a bypass.
