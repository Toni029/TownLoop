TownLoop Privacy Policy

Draft for owner review — not approved for release. Version 2026-10-draft1; prepared October 21, 2026. This draft describes reviewed source code. Operator identity, retention, deletion operations, and service-provider practices must be approved before release.

TownLoop supports resident community activities, dining, announcements, maintenance requests, marketplace listings, and conversations. The accountable operator and final privacy contact must be confirmed by the owner. For community-office inquiries, call 904-771-8839. This phone number is not a confirmed privacy or deletion processing service.

Account and community information

Email/password or Google sign-in uses Firebase Authentication. Resident profiles in Cloud Firestore include name, email, resident address, optional phone and emergency-contact details, profile image, account approval and role, and the terms version and acceptance timestamp. Only provide another person's contact details when you have permission.

Community features store posts, comments, marketplace listings, reactions, activity participation, maintenance requests and status updates, and conversations in Firestore. Selected photos, videos, profile images, and newsletter documents may be uploaded to Firebase Storage. These records support the features you choose, community administration, and access controls. Community content is visible to its intended community audience; maintenance staff and authorized office administrators access records needed for their work. Messages are available to their participants through the service. Do not assume messages are end-to-end encrypted.

Medication and other device storage

The newly prepared native implementation keeps medication and task reminder names, schedules, quantities, and taken status on the device, keyed by the signed-in user. A new app binary containing Expo SecureStore can use protected device storage and migrate existing AsyncStorage records after validating and verifying the protected copy. Older app binaries without that native capability continue to use AsyncStorage; an over-the-air JavaScript update alone does not add the protection. The baseline implementation used AsyncStorage. Ordinary sign-out preserves local reminder records. The owner must verify the released binary, migration, device backup behavior, and explicit deletion path before claiming these protections for installed apps.

The newly prepared web medication implementation persists records separately by user ID in browser IndexedDB, encrypted with AES-GCM using a nonextractable browser cryptographic key stored with the encrypted records. Refreshing the page retains saved records. This browser at-rest protection is not a private vault: scripts running with the site's origin can use the key, and clearing site data or browser storage eviction can remove records. Older web versions saved medication records in plaintext browser localStorage. Explicit copying of those legacy records requires a verified durable write; the original legacy copy remains until separately removed with confirmation. The owner must verify this prepared storage implementation in the released browser version.

These reviewed reminder stores do not contain a cloud-sync operation and are not a medical record service. Information you enter in a post, message, attachment, or maintenance request may be uploaded even if it mentions health or medication. Review all distributed versions and device backup behavior before making a local-only data claim.

Translation, AI, and external services

When maintenance translation is requested, request titles, descriptions/notes, and comments can be sent through the TownLoop translation service to Google Translate or a Gemini fallback. When an authorized editor requests newsletter analysis, PDF content is sent through the TownLoop server to Google Gemini for extraction. AI output can be inaccurate and requires human review. Avoid submitting unnecessary sensitive information. Provider retention, model-training settings, processing locations, and contractual terms have not yet been approved for this release; no promise of zero retention or exclusion from training is made here.

Firebase supplies authentication, cloud database and file services. Expo's update service checks for and delivers app updates. The weather tile queries Open-Meteo for configured community coordinates, rather than requesting your device GPS location. External services receive network requests and may process connection or technical information. The exact production SDK, server, hosting, and update-service logging inventory remains a release-review item. This draft does not assert that no technical data is collected or that data is sold or used for advertising.

Permissions and security

The app asks for camera access when you choose to take an attachment photo and uses the system photo/video picker for selected media. Features can be limited if you decline access. Final Android permissions must be verified from the release manifest. TownLoop uses authenticated Firebase access controls and HTTPS service endpoints; these measures do not guarantee complete security. Device/browser storage is not described as an encrypted health-data vault.

Retention and account deletion

The source does not establish an approved retention schedule for profiles, messages, attachments, operational records, logs, backups, or reports. Those periods, exceptions, and deletion processing responsibilities remain pending owner approval. Signing out, leaving a conversation, or uninstalling must not be treated as deletion of cloud records.

The prepared account-deletion service requires a recently authenticated, verified session and explicit confirmation, then queues a restartable job and marks the account as deletion pending. The worker can disable access and process records. Deletion of owned social posts or listings requires an explicit owner-approved collection policy. Shared conversation history, comments in another person's content, and records without a reviewed policy are held for an owner decision; identity deletion does not establish that all media cleanup is complete. This implementation is not an approved retention schedule or evidence that the service has been deployed.

See the TownLoop account deletion request page for the prepared request route. Before release, the owner must approve any retained categories and reasons, verify that in-app and external request paths work, and test associated records, files, local data, and processing failures. Existing private-history migration also requires a separately reviewed trusted cutover; a prepared migration does not prove older records were converted. This draft does not promise a completion deadline or an already staffed request service.

Questions and changes

The owner must designate the privacy contact, applicable rights-request process, and approved policy effective date. Changes to data handling require a corresponding policy and store-disclosure review. This draft is not evidence of legal or Google Play compliance.
