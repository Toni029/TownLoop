# Native Work Orders checkpoint

Implemented under native/expo-migration with the web WorkOrdersScreen, WorkOrderModal, useWorkOrders, permission utilities and Firestore schema on main a6567cd as references. Main/web are unchanged. Recovery commit 4919a2b is retained; feeb2b8 additionally removes the default newsletter.

- TownLoop heading/mode pills, green gradient request control, ticket SVG outline/barcode, category/title row, one-motion measured expansion, status badges, descriptions, unit/requester metadata, history, original/resolution photos and crew replies.
- Resident-only own-ticket visibility; admin/VIP/crew oversight. Creation follows existing resident/admin/VIP rules. Crew-only notes, required note/photo completion, photo-verified completion, reopen. Author/manager/crew deletion follows the shared reference permissions and confirms first.
- Native request/category form, photo library and camera selection, upload progress, failure/retry, mid-size/full-screen animated dialog, keyboard resize/safe areas, custom TownLoop controls, floating success feedback, accessible labels and touch targets.
- Live newest-first `work_orders` ordered by `createdAt`, approval/profile in `users/{uid}`, Storage uploads in `work_orders/`. Same fields, no additional collection/schema or queue system. Position is calculated from the full newest-first list excluding Done, exactly as the web screen; first active ticket displays In Progress regardless of its stored Queued/Submitted status. Completed tickets remain in history until explicitly deleted.
- Writes are acknowledged before success. Stable submission ids/transactions prevent duplicate records, transactional comments preserve concurrent replies, completion is idempotent and stores proof plus completion metadata atomically. Reopen removes obsolete completedAt/completedBy while preserving history. Browser-only local caches/optimistic false successes were replaced with Firestore listeners and surfaced errors. No production test writes.
- English/Spanish toggle uses the reference's full local phrase/pattern translator. Cloud translation requires a deployed authenticated HTTPS POST `/api/translate` (title, description, comments, targetLang); no deployed origin was found in the earlier backend inspection. No key goes in native. Native uses the same local fallback that the web uses when its server fails.

Validation: TypeScript/lint/model tests, Home and News regression tests, Expo compatibility and Android/iOS exports. Actual native action modules passed 13 local Firestore emulator checks against unchanged rules; 28 isolated layout/role/form checks passed at 320/390/768 px. No fake records were written to production. Fixture screenshots are layout evidence, not a device acceptance test.

Device acceptance still required: real authenticated live accounts, Storage permissions/uploads, camera/library cancellation/denial, native photos/videos/zoom, keyboards/font scaling/TalkBack/VoiceOver, Android back, iOS safe areas, interrupted uploads and repeated taps. Ticket text uses the native font available in the build; the web's Dotrice font is not a bundled local font. Native camera controls/share/gesture behavior and translucent effects have platform differences. Full-app polish is deferred by the user.
